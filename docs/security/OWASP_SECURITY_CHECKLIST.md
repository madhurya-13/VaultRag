# OWASP-aligned security checklist

This is an engineering review mapped to OWASP Top 10 (2025), API Security Top 10 (2023), and ASVS 5.0. It is not a certification or independent assessment. References: [OWASP Top 10](https://owasp.org/projects/top-ten), [OWASP API Security Top 10](https://api-security.owasp.org/editions/2023/en/), [OWASP ASVS](https://asvs.owasp.org/).

| Category / control | Finding and severity | Component and reproduction | Fix / verification | Residual risk |
|---|---|---|---|---|
| API1/API3, ASVS access control | Cross-tenant access would disclose sensitive chunks; Critical | Attempt B document ID or tenant ID as A; see tenant-isolation suite | RLS, composite tenant keys, server tenant context, 404 behavior; PostgreSQL integration and LLM-context assertions | Must retain restricted DB runtime role; run tests on each auth/retrieval change |
| API5, ASVS authorization | Stale grants after revocation; High | Query, revoke READ, immediately repeat same query | Current permission checked during each retrieval; regression proves second request has no source and no additional LLM call | Any future retrieval cache must include permission version/invalidations |
| API2/API3 | Forged role claim could elevate employee; High | Sign a token containing ADMIN role for employee; call admin endpoint | Roles reloaded from DB; M6 forged-role test expects 403 | Token theft remains a concern; MFA not implemented |
| A01/A05, ASVS input validation | Malicious document / path traversal; High | Upload malformed, encrypted, renamed, oversized, excessive-page PDF or traversal filename | Type/content checks, byte and page caps, extraction thresholds and private path containment; upload attack suite | No OCR; parser/library vulnerabilities require dependency scanning |
| A03/API10 | SQL injection / malformed request payload; High | Submit SQL syntax in typed filters/JSON and malformed fields | SQLAlchemy bound parameters and schema validation; existing DB/API tests | Scanner and fuzzing runs still required on changes |
| A04, ASVS session | Wrong JWT issuer/audience accepted; High | Sign valid JWT with wrong `iss` or `aud` using application test key | Decoder requires matching issuer/audience; M6 regression returns 401 | HMAC secret compromise permits token minting; use secret manager and rotation |
| A05/API8 | Unsafe CORS or host routing | Send hostile Origin/Host | Explicit CORS, TrustedHost, production config rejects wildcard host/origin | Set exact public origin/host in production |
| A07, ASVS authentication | Brute force / credential stuffing; Medium | Repeated login attempts via proxy | Nginx login rate limit and auth validation | Per-IP limiter can be bypassed via distributed clients; use shared limiter and MFA for production |
| A08/API10 | Dependency or image supply-chain compromise; High | `pip-audit`, `npm audit`, Bandit, Gitleaks, Trivy workflows | CI checks added; inspect actual run outputs before release | Scans cannot detect all vulnerable behavior; image tags should be digest-pinned for release |
| A08 | Malicious PyTorch checkpoint can exploit vulnerable `torch.load`; High | PyTorch versions through 2.9.1 had a `weights_only=True` unpickler issue; see the [upstream advisory](https://github.com/pytorch/pytorch/security/advisories/GHSA-63cw-57p8-fm3p) | Pin to PyTorch 2.15.0, which upstream lists as fixed; CI audits dependencies and the container | Model downloads remain a supply-chain boundary; scan releases and never load user-uploaded model checkpoints |
| A09, ASVS logging | Security action repudiation; Medium | Review tenant audit events after grants/revocations/denials | Append-only security audit log tests; request correlation IDs | Central immutable log retention/alerting is an operator responsibility |
| A10/API4 | DoS via huge request or expensive inference; High | Oversize upload/query burst | PDF/upload limits, bounded RAG controls, timeouts, proxy body and rate/connection limits | Resource ceilings need load measurements and shared controls for multiple replicas |
| A03 XSS, ASVS output encoding | Model output rendered as HTML; High | Return `<img src=x onerror=...>` from fake LLM | React text rendering; frontend regression checks no injected image/handler node | localStorage bearer token is exposed to script running in same origin |
| Infrastructure | DB/Ollama exposed or app runs privileged; High | Inspect Compose service ports, user and capabilities | No host ports for DB/Ollama; app images non-root, drop caps, read-only root FS | Docker host admin remains trusted; add HTTPS reverse proxy before public exposure |

### Tool status

CI now runs Ruff, Bandit on application code, pip-audit, npm audit and Gitleaks. The optional workflow runs Trivy filesystem and image vulnerability/secret/misconfiguration scans. A finding is not considered resolved until the workflow result and affected dependency are reviewed. This checklist does not claim OWASP certification or complete security.
